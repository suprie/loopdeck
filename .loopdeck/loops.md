In the common case this costs nothing: a human watching the app live sees the same pending card via the existing `agent_pending_question`/`_permission`/`_plan` surfaces (shared `AppState`, not tied to the run's no-op channel) and can answer it directly, so the turn completes normally and `TurnParked` is never reached. `cancel_run`'s doc comment corrected to match: `fire_interrupt` now genuinely interrupts an *actively streaming* phase turn, but still can't reach an already-parked card. 7 new/updated Rust tests (`turn_deadline_expired_error` × 2, `phases_blocked_by_park` × 4 in `run_executor.rs`, plus the 3 call-site updates).
