## Stage 3 Addition — In-Place PRD/Epic Markdown Editor

Adds the ability to edit PRD files (and the epic README) directly in the Epics tab, with a Write/Preview toggle. No new dependency — composes the existing `Tabs` + `Textarea` + `Markdown` primitives, mirroring `EditDescription`'s edit-then-save pattern.

This is an **addition to Stage 3** scope (alongside the skill split in `prd-skill-split.md`). It's independent of the skill split and can land before or after it.

### 1. Backend: sandboxed file read/write (`epic.rs`)

Two functions that read/write any `.md` file under `docs/epics/`. The relative path is validated to prevent escape:

```rust
pub fn read_spec_file(repo_path: &Path, rel_path: &str) -> Result<String, AppError>
pub fn write_spec_file(repo_path: &Path, rel_path: &str, content: &str) -> Result<(), AppError>
```

`rel_path` is relative to `docs/epics/` — e.g. `"support-project-management/prd-spec-layer.md"` or `"support-project-management/README.md"`.

**Sandboxing** (mirrors `list_dir_entries`'s canonicalize + starts_with guard):
1. Join `repo_path/docs/epics/` + `rel_path`.
2. Canonicalize the `docs/epics/` root.
3. Canonicalize (read) or canonicalize-parent (write — the file may not exist yet on write) the target.
4. Verify `target.starts_with(&epics_root)` — rejects `../../etc/passwd` escapes and symlinks pointing out.
5. Enforce `.md` extension (the editor only edits markdown specs).

`write_spec_file` does **not** re-parse/validate the frontmatter — it's a raw file write. If the user breaks the frontmatter, the next `parse_epics` call logs the error and skips that file (existing lenient behavior). This matches how git treats the file: it's the source of truth, the parser is a reader.

### 2. Backend: commands (`commands.rs` + `lib.rs`)

```rust
#[tauri::command]
pub async fn read_spec_file(path: String, rel_path: String, _state) -> Result<String, AppError>

#[tauri::command]
pub async fn write_spec_file(path: String, rel_path: String, content: String, _state) -> Result<(), AppError>
```

Standard path-existence guard (like `get_decisions`), then delegate to `epic::read_spec_file` / `write_spec_file`. Register both in `generate_handler!`.

### 3. Frontend: `SpecEditor.tsx` (Write/Preview tabs)

A self-contained editor that takes a `relPath` + `projectPath`, loads the raw file, and saves on demand:

```
┌─────────────────────────────────────────────┐
│  prd-spec-layer.md          [Write][Preview] │  ← filename + Tabs
├─────────────────────────────────────────────┤
│                                              │
│  ---                                         │  ← Write: Textarea (mono font)
│  prd: prd-spec-layer                         │
│  epic: support-project-management            │
│  ...                                         │
│  ## Phases                                   │
│  ### Phase 1 — Core structs and parser       │
│  - [ ] Define Epic and Prd structs           │
│                                              │
│              [Cancel]  [Save]                │  ← footer
└─────────────────────────────────────────────┘
```

- **Tabs**: `Tabs` primitive with two `TabsTrigger`s ("Write", "Preview").
- **Write tab**: `Textarea` (mono font, min-height ~400px, resize-y). Bound to local state initialized from `readSpecFile`.
- **Preview tab**: the existing `Markdown` component rendering the body (frontmatter stripped for preview — show it as a fenced block or hide it; lean: hide frontmatter, show only the body, since the frontmatter is metadata the user rarely tweaks in preview).
- **Save**: calls `writeSpecFile`, then `onSaved` callback (parent refetches epics). Toast on success/error.
- **Dirty indicator**: if the textarea content differs from the loaded content, show a dot next to "Save" and confirm before Cancel.
- **Loading state**: spinner while the file loads.

### 4. Frontend: wire into `EpicsPanel.tsx`

- **Edit button** on each PRD card header (next to the status badge): a `Pencil` icon. Clicking sets `editingPath` state to that PRD's relative path (`<slug>/<file>`), and the `SpecEditor` renders in place of (or expanded below) that PRD's phase checklist.
- **Edit button** on the epic header: same pattern, edits `<slug>/README.md`.
- When `editingPath` is set, the editor replaces the card's body. Cancel/Save clears `editingPath` and refetches.
- The PRD's relative path is derived from the parsed `Epic.slug` + `Prd.file` (already carried on the structs from Stage 1).

### Out of scope
- No frontmatter form-editor — raw markdown editing only. A structured form for frontmatter fields is a later refinement.
- No diff view — the editor overwrites the whole file on Save. Git is the diff/history layer.
- No editing in the cross-project `/epics` view — that stays read-only.
